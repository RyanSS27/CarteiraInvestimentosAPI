Como o projeto funciona

Entenda a lógica por trás da consolidação da carteira

A aplicação foi desenhada para transformar um histórico bruto de operações em uma visão consolidada, calculando o preço médio de forma dinâmica e consumindo dados de mercado em tempo real.

Fluxo Principal de Uso

Cada etapa utiliza os dados anteriores para chegar ao resultado final.

Etapa 1 Registre transações
Etapa 2 (INTERNO) Preço médio pago é calculado
Etapa 3 Consulte a carteira
Etapa 4 (Externa) Consulta da cotação atual e sua rentabilidade
✨ Resultado

A Matemática da Carteira

📦

1. Quantidade em Carteira

O saldo atual é a diferença exata entre as aquisições e as vendas. O sistema possui travas de validação para impedir que uma venda ultrapasse o saldo existente.

Fórmula
Qtd Atual = Compras − Vendas
🎯

2. Preço Médio (Custo Unitário)

Representa o custo médio real pago por ação. Ele é recalculado a cada nova compra. Vendas reduzem a quantidade, mas preservam o preço médio histórico.

Fórmula
Novo PM = [(Qtd Atual × PM Atual) +
(Qtd Comprada × Preço Compra)]
÷ (Qtd Atual + Qtd Comprada)
💸

3. Lucro ou Prejuízo

A diferença nominal entre o que foi efetivamente gasto para montar a posição (Total Investido) e o que essa posição vale hoje no mercado (Cotação via Brapi).

Fórmula
Resultado = (Qtd × Cotação Atual) −
(Qtd × Preço Médio)
📈

4. Rentabilidade (%)

A métrica que transforma o resultado nominal em um indicador percentual, permitindo comparar o desempenho de ativos de diferentes faixas de preço de forma justa.

Fórmula
Rentabilidade = [(Valor de Mercado −
Total Investido) ÷ Total Investido] × 100
⚠️

E quando a cotação falhar?

Se um ticker não for encontrado ou ocorrer instabilidade na comunicação com o serviço externo, a API aciona um mecanismo de fallback seguro. O ativo afetado utiliza seu próprio Preço Médio como referência de cotação atual.

  • O Lucro/Prejuízo deste ativo fica temporariamente em R$ 0,00.
  • A rentabilidade do ativo assume 0,00%.
  • O cálculo consolidado do restante da carteira não é interrompido.

Arquitetura e Engenharia

A aplicação adota a Arquitetura Hexagonal (Ports and Adapters), isolando completamente as regras matemáticas e o domínio de negócios da infraestrutura tecnológica. Isso garante que o núcleo da aplicação desconheça se os dados vêm do MongoDB ou se os preços são consumidos da Brapi.

Padrão Arquitetural Domain-Driven Design (DDD)
Padrão de Acesso Repository Pattern
Comunicação Externa Client Flurl HTTP

Objetivo do Projeto

Este software possui um escopo intencionalmente enxuto. O foco não é reproduzir uma corretora comercial, mas sim demonstrar domínio na construção de uma API REST escalável capaz de persistir dados no-SQL, processar regras de negócio estritas, integrar serviços de terceiros, aplicar injeção de dependência e entregar uma resposta limpa e consolidada através de DTOs.
